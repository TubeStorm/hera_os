The HERA case study must become specific and sharp.

The story is not:

“I built an AI workspace.”

The story is:

AI products are powerful, but they break trust because users cannot see what the system remembers, what files exist, what agents did, why something cost money, or whether the UI is telling the truth.

HERA is a product/design experiment in making agentic AI visible, controllable, and safer for non-technical builders.

Rewrite the HERA case study with these sections:

* The trust problem in AI tools
* Why normal chat UI breaks down
* Product model
* My role
* What I designed
* Hard decisions
* What broke and how the model improved
* What this proves about my product skill

Use concrete systems:

* Global Iris assistant
* room-based workspaces
* canonical chat integrity
* file-aware chat
* attachment truth
* memory blocks
* Composer 2.0
* permissions
* goals / tasks
* Life OS
* skills / tools catalog
* surface actions
* visible action drawers
* avoiding ghost messages and fake success

Use stronger language:

* I designed the trust layer for an AI workspace.
* I turned invisible agent behavior into visible system states.
* I separated global assistant behavior from room-scoped work.
* I designed interfaces for what the AI saw, did, saved, forgot, and cost.
