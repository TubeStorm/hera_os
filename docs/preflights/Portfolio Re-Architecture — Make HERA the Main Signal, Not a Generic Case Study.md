* The capability model: agents, skills, tools, catalog, permissions

* burn tracking showed why cost must be part of the UX

This section is important because it proves maturity.

# Voice Principles

## 1. Say the plain thing first

Use direct sentences.

Good:

Chat is a bad place to manage work.

Bad:

Traditional chat interfaces often struggle to support durable agentic workflows.

Good:

I wanted AI work to feel like entering a room.

## 2. Be specific before being impressive

Every strong line should point to an object, decision, failure, or screen.

Good:

Iris stopped being a room because that made the assistant’s scope confusing.

Bad:

I optimized the assistant architecture for scalable cross-surface interaction.

Good:

Attachments had to become real room files, not decorative chips.

Bad:

I improved file-aware workflows for enhanced trust.

## 3. Keep the edge, remove the profanity

Favour’s private voice has intensity. Public copy should keep the force, not the swearing.

Private energy:

“This is useless if the user can’t see what the AI actually did.”

Public version:

If the user cannot see what the AI did, the interface is lying by omission.

Private energy:

“Work should not feel like wrestling with a machine.”

Public version:

Work should not feel like wrestling with a machine.

That one can stay.

## 4. Do not over-explain obvious things

Cut paragraphs that repeat the same point.

If a sentence says the same thing as the previous sentence, delete it.

If a section says “trust” five times, rewrite it with actual examples.

Use shorter sections.

Use sharper headings.

Use concrete product objects.

## 5. Show obsession without sounding unprofessional

The site should feel like Favour cares deeply.

It should not feel sanitized to death.

Allowed tone:

* “I built HERA because chat alone is not enough.”
* “The game layer is not decoration. It is how the system explains itself.”
* “I care about the part of AI that breaks after the demo.”
* “If the system spent money, changed a file, or forgot context, the user should know.”
* “Good tools should make people want to work.”

Avoid:

* “I am passionate about innovation.”
* “I craft seamless digital experiences.”
* “I leverage AI to empower users.”
* “I design delightful experiences.”
* “I am a multidisciplinary storyteller.”
* “I bridge creativity and technology.”
