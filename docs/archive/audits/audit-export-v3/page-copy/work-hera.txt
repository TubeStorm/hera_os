HERA OS — an operating system where AI work is visible

HERA is a local-first, game-inspired AI workspace where agents, tasks, memory, files, and cost are visible parts of an operating system instead of hidden chat behavior. I designed it and I’m building it — backend, frontend, and the pixel world.

Why I built it

Most AI tools still feel like text boxes attached to invisible machinery. You type, wait, and hope. You can’t see what the AI knows, what it’s doing, what it saved, what it forgot, or why it failed. If it spent your money, you find out on the bill.

I think that’s why AI still feels too complicated for most people — not just non-developers. The jargon is hostile, the state is hidden, and the interface is a scroll of text pretending to be a workspace.

HERA started from a different belief: AI should feel like a place you can enter. A workspace with rooms, visible agents, task boards, readable memory, real files, logs, and cost. Not magic. Not a black box. A system you can see and direct — and one that’s actually fun to be in.

The product idea

HERA is built like a simulation game because AI systems and game systems have the same shape: states, actions, rules, costs, consequences, progress. Game design spent decades making that shape intuitive. Nobody had applied it to AI.

So in HERA, an agent running a research task isn’t an invisible process — it’s a character at a desk, in a room that belongs to your project, with the task pinned to a board and the cost landing in a ledger. Same underlying operation as any agent framework. Completely different level of understanding for the person watching.

The game layer is not decoration. It is how the system explains itself.

What makes it different
Chat is not a workspace. A room has a team, a task board, memory, files, and a cost history. The chat is one surface inside it — not the room itself.
The AI’s actions must be visible. Tool runs, file writes, task changes — each lands in chat and in the ledger as a receipt.
Code emits the proof, not the model. HERA assumes the model will claim things it didn’t do. Every receipt is generated by code the model can’t fake.
Local-first is the trust architecture. Rooms, files, memory, and chats stay on your machine. AI calls go straight to your chosen provider. A breach of HERA’s servers would expose your email, not your ideas.
Memory should admit uncertainty. Memory blocks are readable and editable. The goal is an assistant that says “I don’t see that in what I have” instead of guessing.
Cost should be visible. Every turn is costed. Unknown cost shows as “—”. Never a comforting fake zero.
Tasks are structured work, not vibes. Status lifecycle, review gates, budgets, and a spend history per task.
What I actually designed

Seven product systems. Each exists because something specific went wrong without it.

The visible OS

The Void, rooms, pixel agents, Life OS. Work happens in places you can see, done by characters you can watch — not in an invisible backend.

The assistant model

Global Iris is an OS-level rail that follows you everywhere. Rooms hold scoped work. Iris used to be a room — that was wrong, and fixing it defined the whole model.

The work model

Goals, tasks, subtasks, review gates, blockers. An agent cannot advance past a step until the user accepts it. Structured work, not vibes.

The trust model

A typed event ledger, action receipts in chat, one canonical transcript, files that actually exist. The code emits the proof — never the model’s word.

The context model

Memory blocks you can read and edit, pinned room truth, rolling summaries, real attachments. You can see what the AI thinks it knows.

The cost model

Per-turn burn in Life OS, budgets per task and room, cheap models for heavy lifting. Unknown cost renders as “—”, never as $0.00.

The capability model

Agents, skills, and tools in a searchable catalog with permission modes — “approve safe actions” instead of nagging on every step.

What using it looks like
A creator with an idea starts a room and asks Iris to help structure the work. Iris can propose agents and tasks — the person approves them; nothing deploys itself.
A user attaches files and can verify the AI actually saw them, because attachments become real files in the room, not decorative chips.
An agent runs a task. The user sees what changed, what it cost, and what failed — in chat, on the task, and in the ledger.
Someone checks memory blocks before a big ask, because they want to know what the AI thinks it knows — and they can correct it.
What broke — and what it taught me

HERA’s model wasn’t designed in advance and executed cleanly. It was corrected into shape by failures. These are the ones that mattered:

Iris was a room

The assistant lived in the same list as project rooms, and her scope stopped making sense. Fix: Iris became a global OS rail. The failure defined the assistant model.

The assistant blocked the app

The first Global Iris was a centered modal that blurred the workspace she was supposed to help control. Fix: a right rail that pushes work aside instead of covering it.

Ghost chat states

The live transcript and the reloaded transcript could disagree — turns half-finished, replies duplicated. Fix: the transcript became a system of record with integrity rules.

Phantom attachments

Files looked attached but never reached the model. Fix: attachments became real room files on disk, with visible chips — or they don’t claim to exist.

Context got expensive

Injecting everything made every turn slow and costly. Fix: memory blocks, compaction, and a catalog agents query instead of carrying every tool description.

Permissions became nagging

Confirming every safe action trained people to click through. Fix: permission modes — safe read-only tools run free, destructive actions still ask.

Cost was invisible

Money left quietly. Fix: burn tracking with one honest rule — if the cost is unknown, show “—”, never $0.00.

Every one of these failures sharpened the same rule: the system must tell the truth about its own state. Not the model — the system.

Why it matters for AI products

Chat apps have no project persistence and no cost visibility. Code agents are for developers only. Agent frameworks require programming. Workflow tools have no memory. Almost everything popular today still hides what the AI knows, what it did, what it cost, what changed, what failed, and where the work lives.

HERA is a bet on the layer between the user and the model — the part providers can’t own: making AI work legible, spatial, and accountable for people who don’t write code. Models get cheaper every quarter. The interface that makes them usable is the durable problem.
